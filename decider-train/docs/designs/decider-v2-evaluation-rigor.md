## Problem Statement
`decider-v2` proposes a 4D block attention mask, shared position IDs, and `head=v2` context stack with rank features for scoring options in autonomous driving Bird's-Eye-View (BEV) decision tasks.
While the initial smoke run demonstrated a raw delta of +4.60 pp over the baseline replica, the benchmark verdict is currently **NOT SEPARABLE** because condition (d) `seeds >= 3` was violated (only 1 seed was executed). In scientific ML evaluation, run-to-run training variance can masquerade as architectural gain. No superiority claim or model release is valid until a multi-seed paired bootstrap condition is satisfied.

## What Makes This Cool
A completely reproducible, open-weights 0.6B parameter autonomous driving decision model that doesn't rely on hype or cherry-picked single seeds. The benchmark rigorously evaluates:
1. Paired bootstrap over test questions (same question sample pairing).
2. Seed spread bounding (delta must exceed run-to-run variance).
3. Calibration error (ECE) and strict order-invariance (max abs dp <= 1e-5).
4. Direct comparison against published references on JevBench and sysone-bench.

## Constraints
- Python 3.12 / PyTorch 2.7.1 container environment parity.
- GPU training budget: requires clean, reproducible execution across 3 seeds per arm without idle compute waste.
- Determinism & Gates: All four structural gates in `tests/test_core.py` must pass prior to launch.

## Premises
1. **Rigor**: A single seed is statistically invalid. A minimum of 3 seeds per arm (`[0, 1, 2]`) with paired bootstrap is the non-negotiable bar before claiming superiority or publishing weights.
2. **Automation**: Running 3 seeds across baseline replica and decider-v2 must be driven by deterministic configs and automated post-run scoring via `decide.py` directly updating `RESULTS.md`.
3. **Integrity**: Codebase gates (`tests/test_core.py`, tensor shapes, attention masking, position id restarts) must be 100% clean and pass without warnings or uncommitted drift.

## Approaches Considered
### Approach A: Manual Ad-Hoc Multi-Seed Runs
Run seeds individually via CLI flags, manually copy checkpoint paths, and manually run evaluate and decide.
- *Pros*: No new orchestration tooling.
- *Cons*: Prone to operator error, inconsistent hyperparameter overrides, and untracked artifact drift. Ruled out.

### Approach B: Unified Multi-Seed Ladder & Automated Decision Pipeline (Recommended)
Add an explicit multi-seed orchestration runner / harness that:
1. Runs preflight checks (`test_core.py` and dry-run).
2. Sequentially or concurrently executes seeds `[0, 1, 2]` for `baseline_replica` and `decider_v2`.
3. Auto-evaluates checkpoints and runs `decide.py` to produce a verifiable, publication-ready `RESULTS.md`.

## Success Criteria
- [ ] `tests/test_core.py` passes 100% cleanly offline.
- [ ] Multi-seed configs and orchestration script validated.
- [ ] `decide.py` evaluates all 4 conditions (bootstrap CI excludes 0, |delta| > seed spread, |delta| >= 1.0 pp, seeds >= 3).
- [ ] Verified `RESULTS.md` ready for Hugging Face model card publication.
